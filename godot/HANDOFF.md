The two resolvers are **not interchangeable**: GeometryResolver applies generic pattern/vertical-reach rules and stops rays at occupied cells, while StyleResolver applies facing/stance-specific attacks and can pierce units. Do **not** consolidate their targeting loops without tests proving semantics remain intact. Existing board tests cover both paths. No combat logic changed in this audit; no Godot tests run. Candidate future work: profile repeated `targetable()`/line calculations inside `StyleResolver.affected()` before optimizing.

- **Terrain wall construction** — `board_3d.gd`, commit `173482a`: replaced per-tile direction/path pair arrays with direction vectors; load the side texture dimensions at most once per tile when an interior wall is needed. Intended to reduce allocations and repeated lookups; no measured benchmark yet.
- **Upright sprite fitting** — `board_3d.gd`, commit `81ee10b`: cache each upright's world position and unit pixel size to skip repeated projection work while unchanged; invalidate on camera transform/viewport changes and in `_place_camera()`.
